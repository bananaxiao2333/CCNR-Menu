# 04 · 版本号规范

> 版本号的**唯一真源**是 `gradle.properties` 的 `mod_version`。本文规定它怎么编、要同步到哪几处、
> 以及哪道门禁在守着它。

---

## 1. 格式

```
<主版本>.<功能批次>.<修订号>
```

| 段 | 什么时候 +1 | 例子 |
| --- | --- | --- |
| 主版本 | 不兼容的大改（配置格式推翻、需要玩家删配置） | `1.0.0` |
| 功能批次 | 一次**成批**的功能交付（例如新增一种背景类型或一批动作） | `0.2.0` |
| 修订号 | 只修缺陷、只改文档、只调默认值 | `0.1.1` |

三条硬规则：

1. **三段都必须是非负整数**，不要写 `0.1` 或 `0.1.0-beta`；
2. **`0.x` 期间允许配置格式变化**，但变化必须在 CHANGELOG 里写清「旧配置会怎样」
   （本项目的原则是：旧字段读不到就走默认值 + 警告，绝不让菜单打不开）；
3. **版本号不参与任何逻辑判断**——不要写「如果版本 < 0.2 就怎样怎样」，
   那种分支在版本号变化时会静默改变行为。

## 2. 结论

当前版本 `0.3.0` 符合上表：第三次交付——**布局靠左 + 无背景纯文字按钮 + 全白图标 30fps +
黑底彩色文字背景**。新增了一种背景类型、一种按钮外观，重做了默认菜单与内置素材，
属于一次成批的功能交付，因此功能批次 +1、修订号归零。
主版本为 `0`（表示还在开发期、配置格式可能变），功能批次 `3`，修订号 `0`。

## 3. 要同步的地方（四处）

| 位置 | 写法 | 谁在检查 |
| --- | --- | --- |
| `gradle.properties` | `mod_version=0.3.0` | 唯一真源，其余都对照它 |
| `CHANGELOG.md` | 顶部第一个 `## 0.3.0（摘要）` | `VersionConsistencyTest` |
| `README.md` | 「当前版本：`0.3.0`」一行 | `VersionConsistencyTest` |
| `docs/04` 本文 | §2 结论、§3 真源行、§6 对照表 | `VersionConsistencyTest` |

`src/main/resources/META-INF/mods.toml` 用 `${file.jarVersion}` 由构建注入，
**不许手写第二个版本号**（门禁会检查）。

## 4. 交付流程

1. 改完代码 → 判断这次是「批次」还是「修订」；
2. bump `gradle.properties` 的 `mod_version`；
3. 在 `CHANGELOG.md` **顶部**加条目（`## <版本>（<摘要>）`，全角括号、不带方括号）；
4. 同步 `README.md` 的「当前版本」，以及本文 §2 / §3 / §6；
5. `./gradlew build` 与 `./gradlew test -PrunTests` 都要绿。

## 5. CHANGELOG 标题写法

本项目与 CCNR-RP / CCNR-PM 保持一致：

```markdown
## 0.2.1（修升级路径：新的默认配置进不去）
```

- 用**全角括号**，摘要一句话说清这次交付的**主题**，不是逐条罗列；
- 版本号与括号之间不加空格；
- 门禁只校验「版本号是否与真源一致」，不锁死摘要文字——但摘要写不清的后果是别人不知道这次改了什么。

## 6. 各仓库当前版本（对照表）

| 仓库 | 版本 |
| --- | --- |
| CCNR-RP | `2.27.1` |
| CCNR-PM | `0.14.1` |
| **CCNR-Menu**（本仓库） | `0.3.0` |

> 表里的其它仓库版本号**刻意与真源无关**：门禁只校验本仓库那一行，
> 否则每次别人发版都会把本仓库的门禁判红。

## 7. 门禁做了什么

`src/test/java/com/ccnrcom/menu/version/VersionConsistencyTest.java`：

1. `mod_version` 必须是三段数字；
2. CHANGELOG 顶部第一个版本号 == `mod_version`；
3. README 里出现 `mod_version`；
4. `mods.toml` 用 `${file.jarVersion}` 且没有手写当前版本号；
5. `docs/04` 存在且内容足够；
6. `docs/04` 自己引用的版本号与真源一致（**规范文档最容易悄悄漂**）。

> 第 6 条不是洁癖：规范文档里写着自己的版本号，一旦它与真源分叉，
> 下一个照规范办事的人就会照着**错的版本号**去同步——这是别的 CCNR 仓库真实踩过的坑，
> 所以本仓库从第一天就把文档也纳入断言。

测试默认被跳过（`onlyIf -PrunTests`），验收命令必须显式带上：

```bash
./gradlew test -PrunTests
```
