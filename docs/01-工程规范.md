# 01 · 工程规范

> 本项目沿用 CCNR 系列的开发纪律。本文写的是**为什么**，具体做法在代码里；违反纪律的实例记录在文末。

---

## 1. 先读后写，修根因

按「现象 → 调用链 → 根因 → 影响面 → 最小改动 → 实现 → 验证」推进。

不允许用「强制刷新 / 重复发包 / 每帧重建 / 延时重试」掩盖状态错误。本模组里最容易犯的一条是
**每个渲染帧重建贴图**：那会让显存分配器每帧抖一次，帧率看起来还行但生成时间出现规律尖峰。
正确做法是「一张贴图 + 重传像素」（见 `GifBackground.uploadFrame`）。

## 2. 服务端权威（本项目体现为「配置权威」）

本模组没有服务端逻辑，但同一条纪律换个形式存在：**配置是唯一权威**，
代码不许在运行时「猜测作者的意图」。

- 颜色写错 → 用默认色 + 警告，不静默变白；
- 动作写错 → **跳过这个按钮** + 警告，而不是留一个点了没反应的按钮；
- 素材缺失 → 退回原版全景图 + 带文件名与原因的日志。

## 3. 校验只有一份

`MenuAction.parse` 是动作合法性的**唯一**实现，`MenuAction.screen(id)` 这个工厂也走同一套白名单。
不允许出现「配置解析时校验、代码内部随便传」的第二条路（`MenuScreen` 的 `vanillaButtons`
模式就是复用 `MenuAction.screen("options")` 这类常量，而不是自己 new 一个屏幕）。

## 4. 线程边界

- **工作线程只做纯计算**：`ccnr-menu-gif` 线程上跑的 `GifDecoder` 不碰 GL、不读游戏状态，
  产出的是 `int[]` 像素数组（纯堆内存）。
- **GL 调用必须在渲染线程**：贴图创建与 `upload()` 都在渲染线程（工作线程解完后经
  `Minecraft.execute(...)` 回主线程）。
- **`NativeImage` 的创建也在渲染线程**：`FileTexture.fromArgb` 是由渲染线程调用的。

## 5. 对称清理

每个资源都要写清「谁创建、谁释放、什么时候释放」（见 docs/00 §5）。
特别地：**屏幕关闭后到达的异步结果必须被丢弃**——`GifBackground.onDecoded` 第一件事就是检查
`closed`，否则「关掉菜单再打开」会留下没人引用的贴图（GPU 资源泄漏，且只在反复进出菜单时累积）。

## 6. 界面纪律

- **颜色只取自主题**：`MenuTheme` 是唯一的绘制令牌来源，界面代码里禁止写裸 `0x` 色值。
- **同类构件只走共享入口**：铺屏/裁剪/着色一律走 `TextureDraw`；
  按钮一律走 `MenuTheme.drawButton`。分开实现必然出现「图片背景留黑边、精灵图背景不留」这类差异。
- **`setColor` 用完必须复位**：`GuiGraphics.setColor` 是全局状态，忘了复位会让**之后所有**界面
  都带上那层颜色（症状出现在别的界面上，极难联想到背景代码）。`TextureDraw` 用 `finally` 复位。
- **亮底深字**：本模组默认配色里没有亮底按钮；若日后新增，文字色必须同时改。

## 7. 质量与交付

- 编译通过 ≠ 正确；**未实机验证的必须明说**（本项目禁止起客户端，见 §8）。
- 无占位、无空壳、无「只为过编译的假逻辑」。
- 提交前查 `git diff`，单一职责，Git 操作只限任务授权。

## 8. 测试纪律（本项目的特殊约束）

**禁止启动服务器/客户端做测试**（用户在实机测试，起进程会干扰）。因此：

- 能测的逻辑必须**抽成纯类**：几何（`MenuGeometry`）、计时（`FrameClock` / `FrameTimeline`）、
  解码（`GifDecoder` / `GifComposer`）、配置解析（`MenuConfig.parse`）、动作白名单（`MenuAction`）。
- 单测跑在 headless AWT 上即可（GIF 解码不需要显示设备），`build.gradle` 已设
  `java.awt.headless=true`。
- 测试默认**被跳过**：`./gradlew test -PrunTests` 才执行。验收必须显式带上 `-PrunTests`。

## 9. 实例：本项目刻意避开的坑

| 坑 | 为什么危险 | 本项目的做法 |
| --- | --- | --- |
| 用 mixin 换主菜单 | 开发环境正常、打包后因 refmap 失效而静默无效 | 用 `ScreenEvent.Opening.setNewScreen`（docs/00 §3） |
| 动画用「每帧自增」计时 | 速度随帧率变化，卡顿即变速 | 绝对时间求帧号（`FrameClock` / `FrameTimeline`） |
| GIF 只按第一帧解码 | 优化过的 GIF 只写「变化的小块」，会拼出碎片 | 按规范做画布合成与 disposal（`GifComposer`） |
| GIF 直接整包解码 | 3MB 的 1080p×60 帧解出 475MB | 解码前算预算，超了整倍缩小（`GifBudget`） |
| `super.render()` 画背景 | `Screen.render` 会画泥土背景，盖住动画 | 自己遍历 `renderables`（`MenuScreen.render`） |
| 白名单与 switch 两处漂移 | 两边都不编译失败，症状是「按钮点了没反应」 | `MenuScreenMappingTest` 静态钉住 |
| 语言键只在代码侧缺失 | 界面上显示红字原始键，只有打开界面才看得见 | `LangFileTest` 扫描代码+内置配置 |
